# Vanta Market — بوت متجر وتذاكر Discord

بوت Discord لمتجر Vanta Market يعمل على Node.js 20+ باستخدام discord.js v14 وSQLite عبر better-sqlite3. جميع إعدادات المتجر والرتب والقنوات والطلبات محفوظة في قاعدة البيانات، وتدار من أوامر السلاش. واجهة Discord بالعربية.

## الوظائف

- `/store` ينشر لوحة بأزرار منتجات قابلة للتعديل، ويحذف زر Support القديم من اللوحات التي يستطيع البوت الوصول إليها.
- المنتجات الافتراضية: Minecraft Java + Bedrock بسعر $13، وخدمة رقمية مرخّصة بسعر $8. يمكن تغييرها أو حذفها وإضافة غيرها.
- يبدأ زر المنتج تذكرة خاصة، ويسجل العميل الكمية، يختار LTC، ثم يكتب **تأكيد** لإرسال الطلب للمراجعة. يمكنه الإلغاء قبل الإرسال.
- لكل طلب رقم فريد وسجل ثابت للمنتج والسعر والكمية والعميل والحالة. النقر المتكرر لا ينشئ طلبًا ثانيًا.
- الطلبات في قناة Orders تحتوي منشن العميل والأونر/عضو الإشعارات وأزرار قبول ورفض. الرفض يحفظ المنفذ والسبب الاختياري.
- القبول يحفظ هوية الموظف، ينشئ تذكرة مناقشة خاصة أولًا، ثم يحذف تذكرة الطلب الأولى بعد نجاح إنشاء التذكرة الجديدة وتسجيلها.
- الدفع يدوي فقط: يمكن للستاف إرسال عنوان LTC، وتأكيد استلامه يدويًا، ثم إكمال الطلب. قبول الطلب لا يعني أن الدفع تم.
- صلاحيات التذاكر تمنع رؤية `@everyone` وتسمح للعميل والأونر ورتب الأدمن المحددة والبوت. زر حذف القناة للستاف/الأدمن فقط؛ السجل لا يُحذف.
- `/cmd` يعرض الأوامر المتاحة مع توضيح الأوامر الإدارية والستاف.

### أوامر الإدارة

تشمل الأوامر: `/setowner`, `/removeowner`, `/addadminrole`, `/removeadminrole`, `/listadminroles`, `/addstaffrole`, `/removestaffrole`, `/liststaffroles`, `/setorderschannel`, `/setticketcategory`, `/setpaymentwallet`, `/setmentionuser`, `/setbuttonname`, `/setticketname`, `/addproductbutton`, `/removeproductbutton`, `/editproduct`. يدعم البوت أيضًا `/custom_button` للتوافق مع الاستخدام السابق.

تعديل إعدادات البوت متاح للأونر ورتب الأدمن فقط. رتب الستاف التشغيلية التي تضيفها عبر `/addstaffrole` تستطيع إدارة الطلبات والتذاكر والدفع لكنها لا تستطيع تعديل إعدادات البوت. كلا النوعين المخول يرى التكتات لتأدية عمله. إذا لم تُضبط أي رتبة أدمن أو أونر، يسمح البوت مؤقتًا لعضو يملك `Manage Guild` بتهيئة أول صلاحية. `STAFF_ROLE_ID` الاختياري يُضاف كرتبة أدمن أولية. عيّن الأونر عبر `/setowner` قبل استقبال الطلبات.

### حالات الطلب

`Pending` → `Accepted` → `Payment Pending` → `Paid` → `Completed`. يمكن رفض الطلب بحالة `Rejected` أو إلغاؤه قبل المراجعة بحالة `Cancelled`. لا تنتقل حالة الدفع إلى `Paid` تلقائيًا، ولا تعد الصورة وحدها إثباتًا كافيًا.

## المتطلبات

- Node.js **20+**
- حساب بوت في Discord Developer Portal
- سيرفر Discord، ورتبة للموظفين، وقناة نصية للطلبات، وفئة للقنوات الخاصة
- تخزين قرص دائم لاستمرار قاعدة SQLite. استخدم نسخة احتياطية دورية للملف وقاعدة WAL.

## الإعداد

1. أنشئ تطبيقًا وبوتًا من [Discord Developer Portal](https://discord.com/developers/applications)، ثم انسخ رمز البوت سرًا. لا تشاركه ولا تضفه إلى Git.
2. أنشئ رتبة الموظفين وقناة الطلبات وفئة التذاكر في السيرفر. من إعدادات Discord فعّل **Developer Mode**، ثم انسخ معرّفات التطبيق والسيرفر والرتبة والقناة والفئة.
3. أضف المتغيرات إلى Replit Secrets/Environment أو ملف `.env` محلي غير مرفوع إلى Git:

   | المتغير | القيمة |
   | --- | --- |
   | `DISCORD_TOKEN` | رمز البوت السري من Developer Portal |
   | `CLIENT_ID` | معرّف التطبيق |
   | `GUILD_ID` | معرّف السيرفر الذي سيعمل فيه البوت |
   | `STAFF_ROLE_ID` | رتبة أدمن أولية اختيارية؛ تُضاف إلى قاعدة البيانات عند أول تشغيل |
   | `ORDERS_CHANNEL_ID` | معرّف القناة النصية التي تستقبل الطلبات |
   | `TICKET_CATEGORY_ID` | معرّف فئة قنوات التذاكر |
   | `ORDER_NOTIFY_USER_ID` | عضو الإشعارات الأولي الاختياري، ويمكن تغييره بـ `/setmentionuser` |
   | `OWNER_ID` | أونر ابتدائي اختياري، أو استخدم `/setowner` داخل Discord |
   | `LTC_WALLET_ADDRESS` | محفظة LTC ابتدائية اختيارية، أو استخدم `/setpaymentwallet` |
   | `DATABASE_PATH` | اختياري؛ مسار ملف SQLite، والافتراضي `./data/vanta-market.sqlite` |

4. فعّل **Message Content Intent** في إعدادات البوت؛ يحتاجه البوت للتعرّف على كلمتي **تأكيد** و**إلغاء** في تذكرة التأكيد.
5. ادعُ البوت إلى السيرفر بنطاقي OAuth2 `bot` و`applications.commands`. امنحه على الأقل:
   - View Channels
   - Send Messages
   - Read Message History
   - Embed Links
   - Attach Files
   - Manage Channels

   تحقق من إعدادات صلاحيات القنوات والفئة حتى يستطيع البوت إنشاء تذاكر خاصة وتعديل أذونات العميل عند الإغلاق. يجب أن يكون قادرًا على رؤية قناة الطلبات وفئة التذاكر، وأن تكون رتبته أعلى من رتب الأدمن التي تضيفها. لا يحتاج إلى `Administrator`.

   **قيد Discord:** من لديه صلاحية `Administrator` على السيرفر يتجاوز Permission Overwrites ويمكنه رؤية القنوات الخاصة؛ لا يستطيع أي بوت منعه من ذلك. رتبة أدمن مضافة من خلال البوت دون صلاحية `Administrator` لا تتجاوز القيود.

## التثبيت والتشغيل

من جذر المشروع:

```bash
pnpm install --filter @workspace/vanta-market-bot --frozen-lockfile
pnpm --filter @workspace/vanta-market-bot start
```

يسجل البوت جميع الأوامر تلقائيًا كسلاش أوامر خاصة بالسيرفر المحدد في `GUILD_ID`. استخدم `/cmd` لرؤية القائمة. `/addproductbutton` يضيف منتجًا، و`/custom_button` يبقى متاحًا لإضافة زر منتج سريع. استخدم `/store` لنشر لوحة المتجر. الإعدادات الأولية من البيئة تُنسخ إلى قاعدة البيانات فقط إذا لم تكن هناك قيمة محفوظة بالفعل.

للتأكد من صياغة ملف JavaScript:

```bash
pnpm --filter @workspace/vanta-market-bot run check
```

وتشغيل اختبارات قاعدة البيانات والأزرار:

```bash
pnpm --filter @workspace/vanta-market-bot test
```

## التشغيل على استضافة Node.js

شغّل `pnpm --filter @workspace/vanta-market-bot start` مع متغيرات البيئة من Replit Secrets/Environment، ووجّه `DATABASE_PATH` إلى قرص دائم. لا تشغّل أكثر من نسخة للبوت على ملف SQLite نفسه؛ استخدم نسخة تشغيل واحدة لكل قاعدة بيانات.

إذا لم يكن القرص دائمًا، فستفقد قاعدة البيانات الطلبات والتذاكر عند إعادة إنشاء الخادم. احتفظ بنسخ احتياطية آمنة من ملفات قاعدة البيانات، وتأكد من حفظ ملفي `-wal` و`-shm` مع قاعدة البيانات عند نسخها أثناء التشغيل؛ والأفضل إيقاف البوت أو استخدام أداة نسخ SQLite متوافقة.

## حدود البوت والخصوصية

- لا يطلب البوت بيانات محافظ أو كلمات مرور أو عبارات استرداد، ولا يخزنها.
- لا يطلب البوت كلمات مرور أو مفاتيح خاصة أو عبارات استرداد.
- تأكيد الدفع يتم يدويًا بواسطة ستاف مخول؛ لا يُستنتج من صورة تحويل.
- ترقيات SQLite تنقل الجداول القديمة مع الحفاظ على سجل الطلبات والتذاكر والأزرار، ولا تحذف بياناتها.
- يحتوي `data/` و`.env` على بيانات محلية ويستثنيهما `.gitignore` من Git.
